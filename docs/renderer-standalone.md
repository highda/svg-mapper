# Using the renderer without the builder

The renderer does not need the SVG Mapper editor. It needs a `map.json` that follows the [`ClickMapDefinition` contract](data-model.md), written by hand, generated by a script, or produced by a CMS. This guide takes you from nothing to an embedded, working map using only the renderer files, and lists what the builder would otherwise do for you.

The example in this guide is committed as [`examples/minimal/`](../examples/minimal/). CI checks that every map in `examples/` passes the JSON Schema and the builder's semantic validation, and that it renders and responds in Chromium with only the built renderer. See [Conformance in this repository](#conformance-in-this-repository).

## 1. Get the renderer

Use either source. Both give you the same files.

- **Release download.** Each GitHub Release has `svg-mapper-renderer.zip` with:

  | File | Purpose |
  | --- | --- |
  | `clickmap-renderer.js` | Dependency-free browser script that defines the global `ClickMapRenderer` |
  | `clickmap-renderer.css` | Default styles, needed unless you use `shadowDom: true` |
  | `clickmap-renderer.d.ts` | TypeScript declarations for the definition types and the API |
  | `clickmap-definition.schema.json` | JSON Schema (draft-07) for `map.json` |
  | `*.md` | This guide, the renderer API, the data model, and the export format |

- **Build from source.**

  ```sh
  git clone https://github.com/highda/svg-mapper.git
  cd svg-mapper
  npm ci --prefix shared
  npm ci --prefix renderer
  npm run build --prefix renderer        # renderer/dist/clickmap-renderer.js and .css
  npm run build:types --prefix renderer  # renderer/dist/clickmap-renderer.d.ts
  ```

  The schema is committed at `shared/schema/clickmap-definition.schema.json`.

The renderer is not published to npm. Load it with a `<script>` tag. It has no runtime dependencies and needs no server-side code.

## 2. Write the smallest map

A useful map needs one view, a background, and one area with an action. This is [`examples/minimal/map.json`](../examples/minimal/map.json):

```json
{
  "schemaVersion": "1.0.0",
  "project": {
    "id": "project_minimal",
    "name": "Minimal office map",
    "createdAt": "2026-10-05T00:00:00.000Z",
    "updatedAt": "2026-10-05T00:00:00.000Z"
  },
  "settings": {
    "initialViewId": "view_office",
    "sizingMode": "fluid-width",
    "responsive": true,
    "maintainAspectRatio": true,
    "theme": "default",
    "enableHistory": false,
    "enableKeyboardNavigation": true
  },
  "assets": [
    {
      "id": "asset_office",
      "type": "image/svg+xml",
      "name": "office.svg",
      "src": "office.svg",
      "width": 600,
      "height": 400,
      "inline": false
    }
  ],
  "views": [
    {
      "id": "view_office",
      "name": "Office",
      "slug": "office",
      "canvas": { "width": 600, "height": 400 },
      "background": { "assetId": "asset_office", "fit": "contain" },
      "viewport": { "minZoom": 1, "maxZoom": 4, "initialZoom": 1, "panEnabled": true, "zoomEnabled": true },
      "ui": { "showBackButton": false, "showBreadcrumbs": false, "showTitle": true },
      "layers": [
        {
          "id": "layer_rooms",
          "name": "Rooms",
          "visible": true,
          "locked": false,
          "opacity": 1,
          "areas": [
            {
              "id": "area_meeting_room",
              "name": "Meeting room",
              "geometry": { "type": "rect", "x": 40, "y": 40, "width": 240, "height": 160 },
              "style": {
                "default": { "fill": "rgba(37, 99, 235, 0.08)", "stroke": "#2563eb", "strokeWidth": 2 },
                "hover": { "fill": "rgba(37, 99, 235, 0.25)", "stroke": "#1d4ed8", "strokeWidth": 3 },
                "active": { "fill": "rgba(37, 99, 235, 0.4)", "stroke": "#1e3a8a", "strokeWidth": 3 }
              },
              "action": {
                "type": "popup",
                "content": { "title": "Meeting room", "body": "<p>Seats 8. Book it at the front desk.</p>" }
              }
            }
          ]
        }
      ]
    }
  ],
  "popups": [],
  "sharedStyles": {},
  "customEvents": []
}
```

Notes on the fields:

- **Coordinates** are in canvas units. `canvas` is the view's coordinate space (here 600 × 400), and area geometry uses the same units. Other geometry types are `circle`, `polygon`, `path`, and `marker`; see [Areas](data-model.md#areas).
- **The background** references an asset by ID. `src: "office.svg"` is a relative path. With `definitionUrl` it resolves against the URL of `map.json`, so `office.svg` sits next to it. `width` and `height` must be the artwork's intrinsic size. The renderer uses them to fit the image (`contain`, `cover`, `fill`, or `none`).
- **Every area needs all three style states** (`default`, `hover`, `active`). The renderer paints `style` as written and fills in nothing.
- **Actions**: `popup` is used here. For navigation, add a second view and use `{ "type": "goToView", "targetViewId": "view_other" }`; [`examples/campus/map.json`](../examples/campus/map.json) does this. The other actions are `url`, `toggleLayer`, `customEvent`, and `none`.
- **Empty collections are required.** `assets`, `popups`, `sharedStyles`, and `customEvents` must be present, even when empty.
- **Required but not read by the renderer.** Any valid value works for `settings.theme`, `settings.enableKeyboardNavigation` (keyboard support is always on), `ui.showTitle`, `ui.showBreadcrumbs`, layer `locked`, and the `project` timestamps. They exist for the editor or for later use.

To go further, the campus example adds a second view, `goToView` links, tooltips, accessibility labels, and metadata. The full field reference is the [data model](data-model.md).

## 3. Embed it

This is [`examples/minimal/index.html`](../examples/minimal/index.html). Put `clickmap-renderer.js` and `clickmap-renderer.css` from step 1 in the same directory as `index.html`, `map.json`, and `office.svg`:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Minimal office map</title>
  <link rel="stylesheet" href="clickmap-renderer.css">
</head>
<body>
  <div id="office-map" style="max-width: 600px"></div>
  <p id="map-status" role="status">Loading…</p>

  <script src="clickmap-renderer.js"></script>
  <script>
    const status = document.getElementById("map-status");
    const map = ClickMapRenderer.create({
      container: "#office-map",
      definitionUrl: "map.json"
    });
    map.on("ready", (event) => {
      status.textContent = "Loaded " + event.definition.project.name;
    });
    map.on("error", (event) => {
      status.textContent = event.code + ": " + event.message;
    });
  </script>
</body>
</html>
```

Serve the directory over HTTP. Opening it from `file://` blocks the `map.json` fetch. To try the example from a clone:

```sh
cp renderer/dist/clickmap-renderer.js renderer/dist/clickmap-renderer.css examples/minimal/
python3 -m http.server 8000 --directory examples/minimal
```

Then open `http://localhost:8000/`. The copied files are git-ignored. Clicking the meeting room, or tabbing to it and pressing Enter, opens the popup.

To open a page from `file://`, or to avoid a second request, pass the parsed object as `definition` instead of `definitionUrl`. Relative asset paths then resolve against the page (`document.baseURI`) unless you set `assetBaseUrl`.

`ready` fires once after the first view has rendered. Asset problems arrive afterwards as `error` events with code `ASSET_LOAD_FAILED`, so keep an `error` listener for the life of the map. The example page shows the last event, so a missing `office.svg` replaces "Loaded…" with the asset error.

## 4. Validate the file

There are three levels of checking. Each catches more than the one before.

| Level | Tool | Catches | Misses |
| --- | --- | --- | --- |
| Structure | The JSON Schema | Missing or mistyped fields, unknown enum values (`geometry.type`, `action.type`, `sizingMode`, asset MIME types), negative sizes, out-of-range opacity, `schemaVersion` with a major other than 1 | Everything that depends on more than one field, plus two decoder-only rules (below) |
| Decoding | The renderer itself, when it loads the file | All of the above, plus the hit-mask byte length and malformed `data:` URIs in `assets[].src` | Cross-references |
| Semantics | `validateProject`, the builder's Export check | Broken references and inconsistencies between objects | Whether your artwork looks right |

**Structure.** Any draft-07 validator works. With [Ajv](https://ajv.js.org/) from the command line:

```sh
npx ajv-cli@5 validate --spec=draft7 --strict-tuples=false \
  -s clickmap-definition.schema.json -d map.json
```

It prints `map.json valid` and exits 0, or prints the errors and exits 1. `--strict-tuples=false` turns off an Ajv authoring lint about polygon point pairs and does not loosen validation. Geometry and actions are `oneOf` unions, so one mistake is reported once per alternative. Look for the error with the longest `instancePath`. The schema accepts extra properties, so `"x-cms-id": 42` is allowed. A misspelled optional field is ignored rather than reported.

**Decoding.** The renderer decodes every file before it draws anything. A file that fails emits `INVALID_DEFINITION` with a single JSON path (for example `Invalid map.json at $.views[0].canvas.width: …`) and shows that message in the container. An unsupported major version emits `UNSUPPORTED_SCHEMA_VERSION`. When the schema output is hard to read, load the file in your page and read this message.

**Semantics.** Open `map.json` in the [hosted editor](https://highda.github.io/svg-mapper/) with **Open**, then go to **Export**. Errors show in red and warnings in amber, and clicking one selects the object. Nothing leaves your browser. In the editor, relative asset paths resolve against the editor's own URL, so a background stored as a separate file may not show there. The checks still run. They include:

| Check (code) | What the renderer does if you ship it anyway |
| --- | --- |
| `settings.initialViewId` names no view (`BAD_INITIAL_VIEW`) | Emits `VIEW_NOT_FOUND`, then `ready`, and shows an empty map |
| `goToView` target is missing (`BROKEN_GOTOVIEW`) | Activating the area emits `VIEW_NOT_FOUND` and stays on the current view |
| `toggleLayer` target is not in the area's view (`BROKEN_TOGGLELAYER`) | Activating the area emits `LAYER_NOT_FOUND` |
| Background or image references a missing asset (`MISSING_ASSET`, `MISSING_AREA_ASSET`) | Draws nothing for it and reports no error |
| The same ID is used twice anywhere (`DUPLICATE_ID`) | Undefined. For example, clicking the second of two areas that share an ID runs the first area's action |
| Empty or repeated view `slug` (`EMPTY_VIEW_SLUG`, `DUPLICATE_VIEW_SLUG`) | Deep links (`#slug`) can't reach the view, or reach the wrong one |
| Invalid `customCss` (`INVALID_VIEW_CSS`) | Mounts no view stylesheet and emits `INVALID_VIEW_CSS` |
| Zoom values not ordered `0 < minZoom ≤ initialZoom ≤ maxZoom` (`INVALID_ZOOM_RANGE`) | Reports no error, and zoom does not behave as written |
| Unsafe or malformed URLs (`INVALID_URL`) | Ignores the link or attribute |
| Warnings: area without action, unreachable view, unsafe SVG, large raster | Renders normally |

## 5. Data versus `create()` options

`map.json` describes the map. Anything that depends on the host page is a `create()` option and never goes in the file: `container`, `definition`/`definitionUrl`, `assetBaseUrl`, `deepLink`, `choropleth`, `shadowDom`, `css`, and event listeners. Map appearance that should travel with the file is data: area styles, `customCss` per view, `settings.zoomControls`, `settings.directory`, and so on. See [Data versus `create()` options](data-model.md#data-versus-create-options) and the [Renderer API](renderer-api.md#options).

## 6. What the builder does for you

| Builder convenience | Hand authors | Without it |
| --- | --- | --- |
| **Unique IDs** for views, layers, areas, assets, and legacy popups | Must provide. Use any unique strings. | Undefined behaviour (see `DUPLICATE_ID` above). Area IDs also appear in events and deep links. |
| **Slugs**: nonempty, unique, URL-friendly | Must provide, because `slug` is required. | Deep links break as described above. Without `deepLink` enabled, slugs have no effect. |
| **Complete style states** | Must provide `default`, `hover`, and `active` for every area. `disabled` is optional. | The file fails structural validation. |
| **Asset intrinsic size** (`width`, `height`), read from the imported file | Must provide | Wrong values distort or misplace the background, because fitting uses these numbers. |
| **Asset embedding**: data URIs or raw SVG inline, or files under `assets/` | Optional. `src` may be a relative path, an absolute or protocol-relative URL, a `data:` URI, or raw `<svg …>` markup. | Relative files must be deployed where `src` points: next to `map.json` with `definitionUrl`, or under `assetBaseUrl`. Raw markup needs `xmlns="http://www.w3.org/2000/svg"` on its root, or the browser draws nothing. |
| **SVG import and sanitizing**: rejects malformed SVG and strips scripts, event handlers, and external references | Optional for safety | The renderer draws backgrounds and image areas with SVG `<image>`. Browsers never run scripts in that mode, and they don't load the SVG's external resources (web fonts, linked images). Keep artwork self-contained, and use system fonts or convert text to paths. |
| **Rich-content sanitizing** for tooltip and popup HTML | Not needed | The renderer sanitizes this HTML at runtime with DOMPurify and normalizes URLs, whatever produced the file. |
| **`image.hitMask`** for PNG and WebP image areas | Optional | The whole rectangle is clickable. To generate one, use a 1-bit alpha mask of at most 128 × 128 cells, row-major with the least significant bit first, and base64 `data` of exactly ceil(width × height / 8) bytes. See [Areas](data-model.md#areas). |
| **`settings.sizingMode`**, written explicitly on export | Optional | Derived from `responsive` and `maintainAspectRatio`. See [Container sizing](data-model.md#container-sizing). Writing it is clearer. |
| **`accessibility`** (`ariaLabel`, `tabIndex`) | Optional | The area's `name` becomes its accessible label, with default tab order. |
| **`sharedStyleId`**, `sharedStyles` presets | Optional (`sharedStyles` may be `{}`) | Nothing changes, because the renderer only reads each area's own `style`. |
| **The `editor` block** (selection, grid, history) | Omit | Ignored by the renderer and removed by export. |
| **Export validation** (`validateProject`) | Run it yourself as described in step 4 | Broken references reach visitors as described in step 4. |
| **`index.html`, `embed.html`, `hooks.js`, README** in the export ZIP | Write your own host page | None needed. Step 3 is a complete host page. |

## 7. Known limits

- **No npm package or ES module build.** The renderer is a classic script that defines a global. `clickmap-renderer.d.ts` provides types for both the global and `import type` use.
- **No command-line semantic validator.** Semantic checks run in the editor's Export screen, or in this repository's test suite (below).
- **Fetching follows browser rules.** `definitionUrl` needs HTTP(S), plus CORS when `map.json` is on another origin. Use `definition` for `file://`.
- **Background SVG is an image.** Scripts, animations driven by script, and external fonts or images inside it don't run or load (see step 6). Interactive parts must be areas.
- **`customCss` is restricted.** Imports, `url()` and other resource functions, nesting, and global at-rules are rejected. See [Per-view CSS targets](renderer-api.md#per-view-css-targets).
- **One schema major.** This renderer reads `schemaVersion` `1.x.y`. It ignores fields added by newer minor versions and refuses other majors. See [Versioning](data-model.md#versioning).
- **Extra properties are not errors.** The schema and the decoder accept unknown fields, so a misspelled optional field is ignored silently.
- **`popups` is legacy.** Put popup content on the area's `popup` action. Keep `"popups": []`.

## Conformance in this repository

Every JSON file in `examples/` that has a `schemaVersion` is treated as a hand-authored map and checked in CI:

- `editor/src/test/examples-conformance.test.ts` checks that each map passes the published JSON Schema (Ajv), the runtime decoder, and `validateProject` with no errors, and that its relative asset files exist. It also checks that the two code blocks in step 2 and step 3 match `examples/minimal/` exactly.
- `editor/e2e/renderer-standalone.spec.ts` loads each map in Chromium with only `renderer/dist`, using `definitionUrl`. It checks that `ready` fires on the initial view, that the background and every visible area are present, that no request or event fails, and that one `goToView` or popup action works from the keyboard. It also opens `examples/minimal/index.html` as written, with the renderer files served beside it, and clicks the area.

`examples/qa-gallery/fixtures/external-and-broken.json` is the one deliberate exception. It must fail with exactly the errors it exists to test, and it must still load. To add an example, put its `map.json` (and its `index.html` host page, if relative assets should resolve from there) under `examples/`. Then run `npm run test --prefix editor` and `npm run test:e2e --prefix editor`.
